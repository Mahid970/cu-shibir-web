# Deploying cushibir.org

One small VPS (2 vCPU, 2–4 GB RAM, Singapore or Mumbai) runs everything with Docker:
Postgres, the Next.js + Payload server and nightly database backups. Cloudflare sits in front.
Expected cost: about $5–8 a month plus the domain.

## 1. Server

1. Ubuntu 24.04, SSH keys only, `ufw allow 22,80,443`.
2. Install Docker, then either:
   - **Coolify** (recommended): add the GitHub repo as a *Docker Compose* resource pointing at
     `docker-compose.yml`. Coolify adds the reverse proxy and TLS and redeploys on push.
   - **Plain Docker**: `git clone`, then continue with step 3 and put Caddy in front
     (`reverse_proxy 127.0.0.1:3000`).

## 2. Secrets

```bash
cp .env.example .env.production
```

Fill in every value. Generate secrets with `openssl rand -hex 32`:

| Variable | Notes |
|---|---|
| `POSTGRES_PASSWORD` | Database password |
| `PAYLOAD_SECRET` | Signs CMS logins. Changing it logs everyone out |
| `FIELD_ENCRYPTION_KEY` | Encrypts form submissions. **Store a copy offline.** Without it the stored submissions cannot be read |
| `REVALIDATE_SECRET` | For scripts that purge the page cache |
| `NEXT_PUBLIC_SITE_URL` | `https://cushibir.org`, or `https://new.cushibir.org` while testing |
| `SITE_NOINDEX=true` | On staging only |
| Turnstile and Telegram keys | Optional (see `.env.example`) |

## 3. First start

```bash
docker compose --env-file .env.production up -d db
docker compose --env-file .env.production up -d --build web backup
```

- The image build pre-renders pages, so it connects to the database over the host network.
- On first start the server applies the migrations in `src/migrations`.
- Check health: `curl -s 127.0.0.1:3000/next/health` should return `{"ok":true}`.

Then create the first admin at `https://<site>/admin`. The first account becomes super-admin.

Import the public content from the old site from your own computer, through an SSH tunnel to the
server's database (the scripts are not part of the production image):

```bash
ssh -N -L 5433:127.0.0.1:5432 you@server &
export DATABASE_URL=postgres://cushibir:<password>@127.0.0.1:5433/cushibir
# NODE_ENV=production so Payload never "pushes" a development schema into the live database.
NODE_ENV=production npm run import:legacy
NODE_ENV=production npm run seed:english      # English versions of the imported content
NODE_ENV=production npm run search:reindex
```

`seed:english` only writes the CMS's English locale; the Bangla content is never changed. After that, editors add
English for new posts in the admin (each document has a বাংলা / English locale switch).

Share cards for the imported posts are generated by the server's job runner within a few minutes.

## 4. Cloudflare

1. Move DNS to Cloudflare. Proxy (orange cloud) the site's `A` record.
2. **SSL/TLS**: Full (strict).
3. **Cache rules**:
   - Bypass `/admin*`, `/api/*` (except `/api/media/file/*`) and `/next/*`.
   - Cache everything else by origin headers.
4. **Zero Trust → Access**: protect `/admin*`. Allow only the branch's editors' emails (free for up to 50 users).
5. **WAF**: rate-limit `POST` to `/join/*` and `/services/assistance*` (e.g. 20 per minute per IP).
6. **Turnstile**:
   - Create a widget for the domain.
   - Put the keys in `.env.production` and rebuild. `NEXT_PUBLIC_…` values are baked in at build time.

## 5. Going live

1. Staging at `new.cushibir.org` with `SITE_NOINDEX=true`. Check forms, share previews and the admin.
2. Keep the old report builder at `report.cushibir.org` (plan §8).
3. Switch the `cushibir.org` record. Old URLs such as `/blog_details/…` and `/sform` redirect by themselves.
4. Re-scrape the home page and the latest posts in the Facebook Sharing Debugger.
5. Announce on the Facebook page and the Telegram channel.

## Updates

- **Content** needs no deploy: publishing in the CMS refreshes pages immediately.
- **Code**: push to `main`. Coolify rebuilds. Plain Docker: `git pull && docker compose --env-file .env.production up -d --build web`.
- **Schema changes**: run `npm run payload migrate:create <name>` locally, commit the new file in `src/migrations`, and deploy. The server migrates on start.

## Backups and restore

- `backups/` receives a compressed `pg_dump` every night. It keeps 14 daily, 8 weekly and 6 monthly copies.
- Copy it off the server as well, e.g. `rclone sync backups r2:cushibir-backups` from a daily cron.
- Back up the `media` volume too: `docker run --rm -v cushibir-web_media:/m -v $PWD:/b alpine tar czf /b/media.tgz -C /m .`
- **Restore drill**:

  ```bash
  gunzip -c backups/daily/cushibir-<date>.sql.gz | docker compose exec -T db psql -U cushibir cushibir
  ```

  Run it on a scratch server every few months.
